Browser
↓
Remote Server

6. SMART CHAIN ARCHITECTURE

The TM system represents a multi-server tunnel chain.

Each server must understand its role automatically based on the graph.

There are three logical roles:

	1.	Initial / Entry
	2.	Middle / Relay
	3.	Final / Exit

Do NOT make the administrator manually configure every server’s role.

Infer the role from graph topology.

Example:

A → B → C

Then:

A = Initial
B = Middle
C = Final

If:

A → B

Then:

A = Initial
B = Final

If:

A

with no outgoing connection:

A = Initial + Final

If:

A → B → C → D

Then:

A = Initial
B = Middle
C = Middle
D = Final

The graph is the source of truth.

7. SMART ROUTING BEHAVIOR

The routing logic must be generated from the graph.

The first/initial server creates the client-facing configuration.

If the initial server has NO next server:

Client
↓
Initial server
↓
Destination website

If the initial server has a next server:

Client
↓
Initial server
↓
Next server
↓
Destination website

For:

A → B → C

Traffic should logically become:

Client
↓
A
↓
B
↓
C
↓
Destination

The administrator should NOT have to manually specify “initial”, “middle”, and “final” for every node.

The graph determines this.

9. TM PATH ROUTING

The initial server’s TM route should use:

ws/TM/uuid

when there is no next server.

This should route directly to the destination through the initial server.

If the initial server has a next server, the route should become:

ws/nextTM/uuid

and traffic should be forwarded to the next server.

The next server must know which subsequent TM route to use based on the graph.

For example:

A → B → C

The system should derive something equivalent to:

A:
ws/nextTM/uuid
↓
B

B:
next TM hop
↓
C

C:
final destination

Do NOT hard-code only one or two servers.

The algorithm must work for arbitrary chain lengths.

25. IMPORTANT ARCHITECTURE RULE

The visual graph is NOT the tunnel itself.

The graph is the source of truth from which the real tunnel configuration is generated.

Therefore:

Graph
→ topology validation
→ role calculation
→ route calculation
→ TM inbound/routes
→ remote server synchronization
→ actual tunnel/config generation

Never implement a fake visual graph where the lines look connected but the backend does nothing.

Every graph change that is applied must produce real backend configuration.

Iran
